# Fix: chitking init must generate .opencode/package.json

## Problem

`chitking init` generates `.opencode/plugins/inject-chitking-context.js` (ESM) but does NOT generate `.opencode/package.json` with `"type": "module"`. Without this, OpenCode's module loader may fail to load the plugin silently. Node warns: "Module type not specified, reparsing as ES module" — OpenCode may handle this differently and skip the plugin.

## Fix

### 1. Generate `.opencode/package.json` in `chitkingInit`

In `ensureOpenCodeChitkingContextPlugin` (or a new helper), write `.opencode/package.json`:

```json
{
  "type": "module",
  "dependencies": {
    "@opencode-ai/plugin": "^1.14.0"
  }
}
```

Use `writeFileIfMissing` (preserve user edits on re-init).

### 2. Update demo test

`test/demo/demo.test.ts` — assert `.opencode/package.json` is generated by init with `"type": "module"`.

### 3. Update tests

`test/commands/chitking.test.ts` — assert init creates `.opencode/package.json`.

## Acceptance Criteria

* [ ] `chitking init` generates `.opencode/package.json` with `"type": "module"` and `@opencode-ai/plugin` dependency.
* [ ] Re-running init preserves existing `.opencode/package.json` (writeFileIfMissing).
* [ ] Demo test verifies the file is generated.
* [ ] `pnpm build && pnpm test && pnpm lint && pnpm typecheck` pass.
* [ ] Version bumped.

## Technical Notes

* The plugin at `.opencode/plugins/inject-chitking-context.js` uses ESM syntax (`import`/`export default`).
* Without `"type": "module"` in the nearest `package.json`, Node treats `.js` as CommonJS by default.
* The Trellis project's `.opencode/package.json` doesn't have `"type": "module"` either, but OpenCode may handle Trellis plugins differently (e.g., via the `lib/` imports or different loading path).
* Adding `"type": "module"` is the correct fix — it eliminates ambiguity and matches the ESM syntax used in the plugin.
