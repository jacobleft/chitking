# Update AGENTS.md and Chitking Slash Commands

## Scope Update

The latest user request expands this task from root agent instructions to scaffolded Chitking slash-command support for OpenCode and Codex. The AGENTS.md update remains complete; implementation now targets generated adapter surfaces for the full Chitking CLI subcommand set while preserving the same product-boundary constraints and keeping demo generated adapters uncommitted.

## Goal

Improve the repository root `AGENTS.md` so future OpenCode sessions can ramp up quickly and avoid repo-specific mistakes. Keep it compact and high-signal: every line should answer something an agent would likely miss without help.

## Requirements

- Preserve the managed Trellis block in `AGENTS.md` and improve guidance outside that block.
- Keep Chitking framed as a standalone product, not a Trellis derivative.
- Capture verified repo-specific facts from executable sources first: package scripts, TypeScript/Vitest/ESLint config, CLI entrypoints, tests, template copy behavior, demo fixture tests, and existing guidance.
- Include exact developer commands and focused verification shortcuts where useful.
- Document non-obvious architecture and workflow constraints, especially Chitking-native naming, generated scaffold/template surfaces, demo fixture alignment, and committed `research/` versus ignored `.chitking`/`.opencode`/`.codex` boundaries.
- Remove fluff, generic advice, speculation, or exhaustive file trees.
- Inspect existing Chitking CLI/templates/adapter surfaces and `~/projects/trellis` command patterns before adding slash commands.
- Add Chitking-native slash-command entries for OpenCode and Codex for every Chitking CLI subcommand: `ck-init`, `ck-new`, `ck-list`, `ck-show`, `ck-focus`, `ck-rename`, `ck-archive`, `ck-restore`, `ck-delete`, `ck-orient`, `ck-step`, `ck-pack`, and `ck-record`.
- Keep each slash command a thin wrapper around its matching `chitking <command>` behavior. Wrappers must guide CLI usage instead of editing `.chitking/`, `research/`, generated packets, or adapter files manually.
- Preserve Chitking-native names: `chitking`, `.chitking`, `research/`, `ck-*`, and existing `chitking-*` generated role adapter names.
- Update templates, demo fixture source files, ignore rules, and regression tests when scaffold-generated adapter surfaces change.

## Technical Approach

Keep `AGENTS.md` as-is outside any needed small updates, preserving lines between `<!-- TRELLIS:START -->` and `<!-- TRELLIS:END -->`. Add command templates under the Chitking scaffold template tree, wire `chitking init` to write OpenCode command files and Codex skill/slash-command files, preserve user edits on repeated init, and update demo tests to generate adapter surfaces in temporary workspaces instead of committing them under `demo/`.

## Decision (ADR-lite)

**Context**: The existing `AGENTS.md` only contained Trellis harness guidance plus one product boundary note, so agents still needed to rediscover package commands, CLI boundaries, generated surfaces, and demo fixture coupling. The latest request adds a need for first-class Chitking slash-command entry points in AI tools.

**Decision**: Keep the managed Trellis block and short Chitking guide. Add generated command surfaces for every Chitking CLI subcommand for OpenCode and Codex, modeled on Trellis command/skill placement patterns but using only Chitking-native names and CLI commands.

**Consequences**: Future sessions get fast repo orientation and Chitking users get tool-native slash-command shortcuts. The guide and generated-surface tests must stay updated when package scripts, CLI surfaces, or demo/generated-file contracts change. Demo keeps only user-owned source content committed; generated adapters are reproducible outputs.

## Out of Scope

- Changing package scripts or non-command runtime behavior.
- Adding broad tutorials, exhaustive directory trees, or speculative team conventions.
- Rewriting managed Trellis content inside the managed block.
- Adding legacy `rt` / Research Trellis naming or dependencies.

## Technical Notes

- Existing `AGENTS.md` has a managed Trellis block and a standalone product boundary note.
- `README.md` and `package.json` identify this as a private Node >=20 ESM TypeScript CLI package named `chitking`, with binary `bin/chitking.js` loading `dist/cli/chitking.js`.
- `package.json` scripts: `build` runs clean + `tsc` + template copy; `test` is `vitest run`; `lint` and `format` target only `src/` and `test/`; `typecheck` is `tsc --noEmit`.
- `vitest.config.ts` includes only `test/**/*.test.ts` and sets `testTimeout: 10_000`.
- `eslint.config.js` ignores `dist/**`, `node_modules/**`, `scripts/**`, and `*.js`, and enforces strict/stylistic TypeScript rules on `src/**/*.ts` and `test/**/*.ts`.
- `src/cli/chitking.ts` is the Commander CLI surface; `src/commands/chitking.ts` owns filesystem/YAML/Markdown/Git behavior; `src/templates/` contains scaffold templates copied to `dist/templates` by `scripts/copy-templates.js`.
- `test/demo/demo.test.ts` asserts the committed `demo/` fixture omits generated adapter directories, verifies product boundaries, and creates a temp workspace to check current generated OpenCode/Codex adapter files.
- Research artifact: `research/repo-instruction-sources.md`.
