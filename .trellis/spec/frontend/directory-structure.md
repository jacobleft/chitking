# Directory Structure

> Current layout for Chitking's user-facing CLI surface.

---

## Overview

There is no `src/components/`, `src/pages/`, `src/hooks/`, `app/`, or browser asset pipeline in this repository. The current user-facing interface is:

- CLI commands and help text in `src/cli/chitking.ts`.
- Command output generated by `src/commands/chitking.ts`.
- Tool-facing generated adapters/templates under `src/templates/`.
- Public exports in `src/index.ts` for tests and package consumers.

Do not create frontend directories for generic scaffolding. Add them only when a concrete browser/frontend implementation exists, and update these specs in the same task.

---

## Directory Layout

```
src/
├── cli/
│   └── chitking.ts       # user-facing CLI commands, options, help text
├── commands/
│   └── chitking.ts       # command output and state behavior
├── templates/
│   ├── chitking/         # generated role contracts, config, workflow skill
│   └── opencode/         # generated platform adapter/plugin template
└── index.ts              # exports used by tests and consumers
```

---

## Module Organization

- Put new command names, descriptions, arguments, and options in `src/cli/chitking.ts`.
- Put output-producing behavior in `src/commands/chitking.ts` so tests can call behavior without spawning a process.
- Put generated adapter or skill template files under `src/templates/` and ensure build copies them into `dist/templates/`.
- Keep product text consistent across CLI help, templates, generated adapters, and README.

---

## Naming Conventions

- CLI command names are lowercase verbs/nouns: `init`, `new`, `list`, `show`, `focus`, `rename`, `archive`, `restore`, `delete`, `orient`, `step`, `pack`, `record`.
- Generated adapter names use Chitking-native prefixes: `chitking-plan.md`, `chitking-build.md`, `chitking-workflow`.
- Runtime command descriptions should use Chitking product terms: thread, maturity, readiness, role packet, source of truth.

---

## Examples

### Command descriptions live in the CLI file

`src/cli/chitking.ts`:

```ts
program
  .command("orient")
  .description("Print the human checkpoint for the active research thread")
  .action(() => runWithErrors(() => chitkingOrient()));
```

### Generated adapter templates live under templates

`src/commands/chitking.ts` resolves the OpenCode context plugin template from `src/templates/opencode/`:

```ts
const templatePath = path.join(
  getOpenCodeTemplatePath(),
  OPENCODE_PLUGINS_DIR,
  OPENCODE_CHITKING_CONTEXT_PLUGIN,
);
```

### Public surface is exported from one index

`src/index.ts` re-exports command behavior and CLI creation:

```ts
export {
  chitkingFocus,
  chitkingInit,
  chitkingOrient,
} from "./commands/chitking.js";
export { createChitkingProgram } from "./cli/chitking.js";
```
