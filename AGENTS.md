## Chitking Project Boundary

Trellis is installed here only as a development harness for planning, implementation, checks, and journaling.
Chitking remains a standalone product: do not add Trellis as a runtime/package dependency, describe Chitking as a Trellis derivative, or reintroduce legacy `rt` / Research Trellis product naming.

## Repo Map

- Chitking is a private Node >=20 ESM TypeScript CLI package (`type: module`, NodeNext resolution), not a web app or service.
- Public CLI binary: `bin/chitking.js`, which loads built code from `dist/cli/chitking.js`.
- Main Commander surface: `src/cli/chitking.ts`; filesystem/YAML/Markdown/Git command behavior: `src/commands/chitking.ts`; package exports: `src/index.ts`.
- Scaffold templates live in `src/templates/` and are copied to `dist/templates` during `pnpm build` by `scripts/copy-templates.js`.

## Developer Commands

- Install: `pnpm install`
- Build: `pnpm build` (clean + `tsc` + template copy)
- Test: `pnpm test` (`vitest run`)
- Lint: `pnpm lint`; auto-fix: `pnpm lint:fix`
- Typecheck: `pnpm typecheck` (`tsc --noEmit`)
- Format: `pnpm format`; check only: `pnpm format:check`
- After CLI option/help changes: run `pnpm build` then `node bin/chitking.js --help`.

## Tests and Verification

- Vitest includes `test/**/*.test.ts`, excludes `dist`, and uses a 10s timeout.
- Focused tests: `pnpm vitest run test/commands/chitking.test.ts` or `pnpm vitest run test/commands/chitking.test.ts -t "archive requires"`.
- ESLint targets TypeScript in `src/` and `test/`; `scripts/**`, `*.js`, `dist/**`, and `node_modules/**` are ignored, so JS helpers are not covered by `pnpm lint`.
- For docs-only/root instruction edits, at minimum run `git diff --check`. For source, test, template, or CLI behavior changes, prefer `pnpm build && pnpm test && pnpm lint && pnpm typecheck`.

## Generated and Demo Surfaces

- Preserve Chitking-native names in code, docs, templates, and adapters: `chitking`, `.chitking`, `research/`, `chitking-*`, `chitking-workflow`, and `inject-chitking-context.js`.
- `demo/` is a committed regression fixture. `demo/.chitking/` is intentionally ignored; committed user/source surfaces include `demo/research/` and generated adapter context under `demo/.opencode/`.
- If scaffold templates or demo-facing generated files change, update the committed `demo/` fixture and `test/demo/` regression coverage together. `test/demo/demo.test.ts` checks OpenCode adapter parity and product-boundary wording.
